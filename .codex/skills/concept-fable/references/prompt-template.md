# concept-fable — Prompt Template

> 给目标 concept/method/framework 页生成直觉锚点的完整 prompt。供 `concept-fable/SKILL.md` Step 2 调用。

---

## 角色设定

你是一位精通寓言教学的导师。你的任务**不是**解释概念，而是用日常生活中的具体场景（**不是另一个抽象概念**），生成一个寓言或类比，让陌生概念变成可记忆的画面。

---

## 输入

```
概念名：{concept}
当前页面定义：{Compiled Truth 段落，从 wiki/pages/{page-name}.md 提取}
概念类型：{感觉型 | 方法论 | 结构型}（由 SKILL.md Step 2 判断）
```

---

## 任务

### A. 适用边界

#### A.1 三层光谱(选哪类概念用 fable)

三轮 dogfood(陌生化 / jobs-to-be-done / 库存周转率,2026-05-23)实测确认。详见历史草稿 `concept-fable-dogfood.md`「三层光谱」段（已随旧草稿目录退役，见 git history）。

| 概念档位 | SKILL 边界表 | 寓言能锁的部分 | 寓言锁不到的部分 |
|---|---|---|---|
| **感觉型 / 关系型** | 强烈推荐 | 核心感觉(陌生化:"看见熟悉的木勺") | 主动技法面(创作者如何刻意操作) |
| **方法论 / 边界模糊** | 可选 | 视角翻转感觉(JTBD:"问对问题") | 结构化方法学(forces / job statement 等) |
| **结构型** | 警告 | 极泛入门印象(库存周转:"流动好") | 公式、行业基准、trade-off、操作 |

#### A.2 概念类型分档默认行为

按 A.1 档位决定调用 fable 后的默认行为(production 模式;`--draft` 见 A.3):

- **强烈推荐档(感觉型 / 关系型)** → 直接进 Section B 生成 3 候选
- **可选档(方法论 / 边界模糊)** → **先问用户**:「你想要的是"记住感觉 / 视角翻转"还是"学结构"?」
  - 答"记忆 / 视角" → 进 Section B 生成
  - 答"结构" → 不出寓言,建议改用类比图 / cases / decision tree / method 笔记
- **警告档(结构型,如 FIFO、漏斗转化率、库存周转率、布林带)** → 显式确认 + 警告 callout:

> ⚠️ "{concept}" 是结构型概念。寓言可以帮你"记得有这回事",但不能替代结构理解。强塞寓言可能掩盖关键的数值/层级/序列关系。
>
> 仍要继续吗?如果是,本次产出按 B.5「结构型专用产出模板」生成(每候选附「记忆触发」blockquote + 末尾「本寓言不能回答的问题清单」+ 指向结构本身的外部来源)。

等待用户确认。

#### A.3 目标页缺失分支(`--draft`)

**默认 production 调用** `/concept-fable {page-name}`:若 `wiki/pages/{page-name}.md` 不存在 → **abort 并报错**「目标页不存在,无法读取 Compiled Truth 作输入」,不要自行延伸。

**`--draft` 开关** `/concept-fable {name} --draft`:dogfood / 探索性使用专用。
- 跳过 Step 1 的 wiki 页读取
- 用 LLM 对概念的常识知识作输入,**生成前明示用户「输入来自 LLM 常识,请审是否准确」**
- 跳过 Step 5(写入 wiki)/ Step 6(自检 wiki 页规范)/ Step 7(commit)
- 产出仅供评估,**不进 vault**

#### A.4 寓言的边界不止概念类型,也在概念某一面

A.1 光谱按"概念档位"分,但同一档内某个概念可能有多面(感觉 / 视角翻转 / 结构化方法学 / 主动操作技法)。每候选寓言常常只锁住其中**一面**:

- **感觉型若兼具"主动技法"面**(例:陌生化的"创作者刻意构造陌生"):候选默认偏被动唤醒侧,技法面被推到「边界」段轻描淡写
- **方法论类**(JTBD / OKR / 5 Whys 等):寓言只能覆盖"视角翻转"面,**结构化方法学维度寓言不该碰** —— 强塞会模糊框架精度

→ Section B 生成前检查目标概念是否兼有"感觉/视角 + 操作/结构"两面;若是,产出末尾必须明示「本组寓言聚焦 X 面,不替代 Y 面学习」,并把 Y 面的学习路径(类比图 / cases / 公式 / 教材)告诉用户。

### B. 候选寓言生成（3 个）

针对 {concept}，生成 3 个候选寓言：

**约束**：
- 每个 150-300 字
- 使用**具体的日常生活场景**：家庭、市场、邻里、通勤、做饭、修东西、季节变化、自然现象、儿童游戏、动物行为、传统手艺
- **禁止**：
  - 使用比 {concept} 更抽象的词
  - 嵌套另一个抽象概念解释 {concept}（"它就像系统的反馈循环…"❌）
  - 借用现成的著名寓言而不做改造（守株待兔、塞翁失马等不能直接拿来当壳子）
- 3 个候选应来自**不同的生活场景类型**——避免都用职场、都用家庭、都用学习
- **若概念兼有"感觉/视角 + 操作/技法"两面**(参 A.4):3 候选中至少 1 个聚焦**操作面**(行动者主动做了什么),不能 3 个都是"外部 disruption 让人重看"的被动结构

**输出结构**（对每个候选）：

```
### 候选 N — {一句话标题}

{寓言正文，150-300 字}

**检验问题**：
1. {问题 1}
2. {问题 2}
3. {问题 3}（可选）

**为什么这个比喻成立**：
{1-2 句话：核心对应关系 + 边界——比喻**不**对应的部分}
```

### B.5 结构型专用产出模板(警告档继续后强制)

A.2 警告档用户确认继续后,产物**必须**额外满足三件套(SKILL 现状只有警告 callout,不规定继续后产物格式;dogfood 三次都自发加但 LLM 的好心不可靠,本节强制):

**① 每候选寓言尾部必须附**:

> ⚠️ **本段服务于记忆触发,不替代结构本身。** 真正的 {concept} 的[公式/数值结构/行业基准/trade-off]在 [指向结构来源],寓言不展示。

**② 候选末尾追加「本寓言不能回答的问题清单」**(至少 2 条):

```
本寓言不能回答的问题(请另查结构本身):
- (具体问题 1,如"公司库存周转率 8 是好是坏")
- (具体问题 2,如"如何选 ABC 分类阈值")
```

**③ 整个产出末尾追加「结构本身的外部来源」清单**(让用户知道去哪学结构):

```
学结构本身请见:
- 教材章节(如《会计学原理》第 N 章)
- 行业基准(如 [行业] 同业财报、行业报告)
- 公式参考(如 Investopedia / 课程笔记 / 公司内部 wiki)
```

### C. 检验问题的硬要求

检验问题必须是**概念迁移题**，不是寓言细节复述题。

**反例**（不及格）：
- "故事里老王为什么走小巷？"（复述）
- "故事里王婆的菜摊在哪？"（复述）

**正例**（合格）：
- "如果隔壁老王也想走老李这条小巷，但小巷已经被三个人占了，老王该怎么选？请用故事的逻辑回答。"（用寓言推理新场景）
- "假设这条小巷半年后被封了，故事里的人会怎么办？请说出 2 种应对，并用寓言里的角色思维解释。"（用寓言迁移到失效场景）

衡量标准：**听众听完寓言，再被问检验问题，必须用'拿寓言里的因果关系推理一个故事里没明说的情况'来回答**——而不是用寓言里的字面信息回答。

### D. 比喻成立点的硬要求

每个候选必须附"为什么这个比喻成立 + 边界"。

**核心对应关系**：用 1 句话说明"寓言里的 X 对应概念里的 Y"。

**边界**（比喻**不**对应的部分）：必须明确写出寓言**不**能解释概念的哪个面。这是防止学习者把寓言的细节误当作概念本身。

例：

> **为什么这个比喻成立**：寓言里"老王走小巷省 10 分钟"对应 PMF 概念里"用户找到一个明显比现状更省力的路径"。
> 
> **边界**：寓言假设小巷是固定路径，但 PMF 里的"路径"是用户行为模式，会因竞品/平台变化而失效——寓言不能解释 PMF 的时效性。

## 输出格式

3 个候选并排展示，让用户选择或 mix-and-match。**不要**默认选一个写入页面——选择权在用户手里。

```
我为 "{concept}" 生成了 3 个候选寓言（类型判断：{感觉型|方法论|结构型}）：

[候选 1]
[候选 2]
[候选 3]

你想用哪个？也可以告诉我"用候选 2 的故事壳 + 候选 1 的检验问题"这种组合。
```

## 反例库（生成时 self-check 用）

### 反例 1：嵌套抽象

> ❌ "X 概念就像一个反馈循环——当系统检测到偏差时…"

为什么不及格：用"反馈循环""系统""检测"这些比目标概念更抽象的词，没有具体画面。

### 反例 2：现成寓言直接套

> ❌ "X 就像守株待兔——农夫看到一只兔子撞树而死…"

为什么不及格：守株待兔是用户已经熟悉的故事，直接拿来用学习者不会主动复述（脑子里已经被原版占满），起不到锚点作用。改造版可以（"农夫第一次撞兔是惊喜，第二次蹲守等兔是误判经验"），原版不行。

### 反例 3：检验问题复述

> ❌ 检验问题："故事里农夫等了多久？"

为什么不及格：答案能从寓言字面找到，没有推理迁移，相当于背诵原文。

### 反例 4：抹去边界

> ❌ "为什么比喻成立：寓言完美解释了 X 的所有方面。"

为什么不及格：任何比喻都有边界，没写边界等于让学习者把寓言细节当概念本身。

## 当本 prompt 修订时

每次实战后如果发现 prompt 模板有缺陷（生成质量低、检验问题反复写成复述题、某类概念总是触发误警告等），把修订追加到本文件下方的「修订记录」段，并把对应的「实战 Pitfalls」补到 `[[skill-concept-fable]]` 反思页。
