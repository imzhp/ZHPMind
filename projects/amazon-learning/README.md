# Amazon Learning — 学习者蒸馏项目

> 把云飞扬 AIFirst《亚马逊运营培训》课程,从"我上过这门课"蒸馏成"我真正会用的 Amazon 运营知识网"。

当前执行规则见 [codex-learning-workflow.md](codex-learning-workflow.md)：Codex 是过程稿、审查和入库的单一执行者；跨家系评审只作为质量 gate，不再依赖 Claude 主笔。

## 项目背景与定位

### 关键事实
- **我没有 Amazon 实操经验**——曜野业务目前侧重点不是平台运营
- Amazon 是**未来需要加强**的方向(曜野潜在扩展)
- 我手上的素材:课程视频逐字稿(已提取)+ 部分文字资料

### 这决定了一切
**学习者的蒸馏 ≠ 实操者的蒸馏**。两者的核心差异:

| 维度 | 实操者(原始 prompt 的假设) | 学习者(我的实际处境) |
|---|---|---|
| 课程的角色 | 参照系 | 主源头 |
| 信度判断的锚 | 自己的实操数据 | **多源交叉验证 + AI 反驳** |
| 关键风险 | 实操偏差 | **照单全收,记得住但不会用** |
| 输出物 | "我的方法论 v1" | **"我能真正用的知识网"** |
| 能不能写 SOP | 可以 | **不可以**(没做过的事不能教别人) |

### 三个候选目标的取舍

| 目标                                   | 现阶段做不做                       |
| ------------------------------------ | ---------------------------- |
| 知识网(`wiki/pages/concept-*.md` + MOC) | ✅ 主要产出                       |
| 个人方法论(`wiki/pages/method-*.md`)      | ⚠️ 谨慎做——只写"我吸收后理解的",不冒充实操方法论 |
|  (`outputs/amazon-sop-*.md`)         | ❌ **暂缓**,等真有 Amazon 运营经验再写   |

## 6 步工作流(5–6 周渐进)

### W1: 课程知识结构图(0.5–1 day)

**任务**:不急着拆 atomic notes,先画一张**讲师视角的知识结构图**。

**为什么**:理解讲师怎么组织内容、用什么逻辑串。这是博主 prompt 第 1 部分"课程知识地图"的学习者版。

**输出**:`01-course-knowledge-map.md`
- 课程主题分层(选品 / Listing / 关键词 / 广告 / 库存 / 评价 / 数据复盘 / ……)
- 每个主题下讲师讲了哪些具体内容(标题级别)
- 主题之间的依赖关系(谁是基础、谁是延伸)
- **暂不做信度判断**——这一周纯结构梳理

### W2: 硬概念清单 + 多源验证(2–3 h)

**任务**:把课程里所有"硬概念"(术语)提出来,每个做多源验证。

**为什么**:学习者没有实操数据,需要用"多源一致"替代"实操验证"。

**多源验证流程**(每个 concept 至少 3 源):
1. 课程怎么说
2. Amazon Seller Central 官方文档怎么说(去 sellercentral.amazon.com 查)
3. 至少 1 个外部来源(Helium 10 / Jungle Scout 博客 / 知无不言 / 卖家社区)

**信度初判**:
- 三源一致 → 🟢 行业共识
- 课程独有但合理 → 🟡 课程独有
- 多源冲突 / 课程独有且可疑 → 🔴 可疑

**输出**:`02-concept-list.md`(列表格式,30–50 个 atomic concept)

### W3: 方法论清单 + adversarial review(2–3 h)

**任务**:课程里的"判断框架"和"操作方法"提出来,用 [[skill-adversarial-review]] 跑一遍。

**为什么**:方法论不像概念有官方文档可查,需要让 AI 扮演对立专家挑刺。**这步对学习者特别重要——没有实操就反驳是唯一的"现实检验"。**

**步骤**:
1. 列出课程的方法论(15–25 条):"如何选品""如何写 listing""如何投广告"等
2. 对每条方法论,运行 skill-adversarial-review,专家角色填:
   - "设计过 Amazon 购物广告底层算法的资深计算广告专家"(投广告类)
   - "Amazon 平台 Listing 算法工程师"(Listing / 关键词类)
   - "在 Amazon 做了 15 年大类目运营的资深卖家"(选品 / 数据类)
3. 把质疑清单存到 `adversarial-reviews/method-{name}-review.md`
4. 对每条质疑做接受 / 驳回判断,理由留档

**输出**:`03-method-list.md` + `adversarial-reviews/` 子目录

### W4: 概念理解检验(2–4 h,跨整周)— 学习者独有

**任务**:对每个核心 concept 跑 [[skill-concept-fable]],做检验问题。

**为什么**:学习者的核心风险是"记得住但不会用"。寓言检验是把概念从"听过"变成"会用"的关键步骤。

**步骤**:
1. 从 W2 概念清单挑核心 concept(10–15 个,不用全做)
2. 每个跑寓言 prompt(注意:**结构型概念用慎用清单过滤**——比如"FIFO 库存计价"不适合寓言)
3. 答两个检验问题,答案写在 `04-fable-checks/{concept}.md`
4. **答得出来 → 🔵 已掌握;答不出 → 🟠 能记住但不会用,回头补**

**输出**:`04-fable-checks/` 子目录(10–15 个文件)

### W5: 沙盘演练(1 day)— 学习者独有

**任务**:拿一个具体 SKU(曜野的或竞品),走一遍完整流程。

**为什么**:替代不存在的实操数据。卡壳的地方暴露"我以为我会但其实不会"。

**沙盘剧本**:
1. **选品分析**:选一个曜野潜在 SKU,用课程的选品方法论假执行
2. **Listing 撰写**:写一份完整的 Amazon listing(标题 / 五点描述 / 关键词 / Backend search terms)
3. **关键词挖掘**:用免费工具(Amazon 自动建议、Helium 10 试用版)做一轮
4. **广告搭建**:画出广告组架构(SP / SB / SD,自动 / 手动,精准 / 广泛 / 词组)
5. **数据复盘**:假设跑了 30 天,设计需要看哪些数据 / 怎么判断好坏 / 怎么调整

**输出**:`05-sandbox-simulation.md`(整个过程的记录 + 卡壳点清单 + 信度修正)

**关键纪律**:卡壳处不要回看课程"补答案",而是先标 🟠,记录"我卡在哪、我猜怎么做、为什么不确定"。这些卡壳点比答出来的部分更有价值,它们是你**未来真上 Amazon 时第一批要补的功课**。

### W6+: 沉淀进 wiki/pages(全周渐进,后续无限延伸)

**任务**:把 W2–W5 的产出,沉淀到 `wiki/pages/`。

**步骤**:
1. 每个 atomic concept → `concept-amazon-{name}.md`,包含:
   - 定义 + 要点
   - 直觉锚点段落(W4 的寓言)
   - 检验问题 + 我的答案
   - 6 色信度标记
   - 多源验证记录
2. 每个方法论 → `method-amazon-{name}.md`,包含:
   - 方法步骤
   - 适用边界
   - adversarial review 留档(接受 / 驳回的质疑)
   - 6 色信度标记
3. 建 `amazon-operations-moc.md` 做导航
4. 用 `[[]]` 双链连起来

**SOP 暂不写**——等曜野真上 Amazon 业务 6 个月后再启动 `outputs/amazon-sop-*.md`。

## 6 色信度标记(学习者版)

每条 atomic note / wiki page frontmatter 里加 `confidence:` 字段:

| 标记 | 名称 | 定义 |
|---|---|---|
| 🟢 | 行业共识 | 课程讲了 + ≥1 外部来源(官方文档 / 其他课 / 卖家社区)证实 |
| 🟡 | 课程独有但合理 | 仅课程讲,逻辑自洽,无外部矛盾 |
| 🔵 | 我已掌握 | 能复述 + 举例 + 寓言检验通过 + 沙盘演练能用 |
| 🟠 | 我能记住但不会用 | 沙盘演练卡壳,需要补练 |
| 🔴 | 可疑 | adversarial review 或外部资料发现反例 |
| 🟣 | 课程话术 | 完整性凑数,实操弱 |

**关键判断标准**:
- 🔵 是**最重要的标记**,代表"我真的会了"
- 蒸馏完成的标准 ≠ "atomic notes 写完了"
- 蒸馏完成的标准 = "🔵 数量 ≥ 60% 的核心概念"
- 如果跑完 6 周,🔵 < 30%,说明蒸馏失败,只是把课程复述了一遍

## 现实检验:三个替代实操的方案

学习者最大的坑是"没有实操就没有现实检验"。三个替代方案,**至少做一个**:

| 方案 | 投入 | 价值 | 推荐度 |
|---|---|---|---|
| 找 Amazon 卖家做 2-3 次付费咨询(把蒸馏出的方法论给他评分) | 2k-5k | 中-高 | ⭐⭐ |
| 跟踪 2-3 个公开案例(竞品 listing 半年变化、政策公告、卖家社区复盘) | 时间为主 | 中 | ⭐ |
| **小成本实测**:开 Amazon 卖家账号,挂 1-2 个 SKU 跑 3 个月 | 2w-3w | 高 | ⭐⭐⭐ |

**推荐:方案 3**。如果曜野迟早要上 Amazon,这几乎是必经之路,只是早晚问题。早做,蒸馏出来的知识网立刻有真实数据校准,价值翻倍。
