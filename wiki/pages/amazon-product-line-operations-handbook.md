# 亚马逊产品线全链路运营实战手册（拓跋勇）

拓跋勇的 V10 全链路运营手册，是迄今最系统的亚马逊产品线 SOP——核心贡献是把运营从"按模块分别做好"提升到"按时间节点的因果链经营"。手册用 D-60 到 D0（上线准备）和 D0 到 D90（推广经营）两条时间线串联选品、词库、竞品、视觉、广告、定价、库存和决策，七道门控防止在错误方向越跑越快。

## 核心认知：手册的业务逻辑

亚马逊运营是一条单向依赖链：**市场 → 节点 → 商品集 → 产品定义 → 词库 → 竞品 → 用户画像 → 文案视觉 → 广告 → 上线经营**。上游错了，下游无论多努力都是放大损失。手册最常见的卖家失误：

- 产品没定义清楚就写文案；词库没分层就铺广告；成本没算清楚就设价格；上线后只看 ACoS，不看 CTR/CVR/Coupon 核销率/库存现金

核心原则：不是"有哪些模块要做"，而是"每个时间节点应该完成什么"。

## D-60 到 D0：上线准备路线图

| 时间节点 | 核心问题 | 关键产出 |
|---------|---------|---------|
| D-60 到 D-45 | 值不值得进入？ | 产品线方向卡、市场雷达、节点池、商品集初判 |
| D-44 到 D-30 | 第一款产品做什么？ | 产品 Brief、产品定义九宫格、供应链可行性 |
| D-29 到 D-15 | 页面和产品是否互相证明？ | 5D 词库、竞品库、视觉脚本、包装说明书 |
| D-14 到 D-7 | 广告、价格和库存是否能承接？ | 广告架构、预算池、Coupon 风控线、现金灯 |
| D-6 到 D0 | 是否可以正式上线？| 上线九包齐套，硬错误清零，Day 0 监控表 |

**七道门控**（防止在错误方向加速）：市场门控 → 节点门控 → 商品集门控 → 产品门控 → 词库门控 → 页面门控 → 经营门控 → 扩展门控。门控不过，不进入下一站。

## 商品集：选品的真正决策单元

商品集不是大品类，也不是单个 ASIN，而是一组"用户任务、核心机制、产品形态、搜索意图高度接近"的产品集合，用于回答："这个节点里，用户到底在买哪类解决方案？"

**从节点到商品集的漏斗**：定义边界 → 拆搜索入口 → 抓 ASIN 池 → 清洗去重 → OCR/深抓证据层 → 商品集矩阵 → 价格容忍度结构 → Go/Conditional Go/Pivot/Hold/No-Go 闸口

**ASIN 清洗关键动作**：父 ASIN/产品族去重（防止一个变体家族被误判为多个机会）、捆绑剔除、低销量标记（区分核心样本与观察样本）、产品形态修正。

**价格容忍度判断规则**：
- 低价主导（低价销量占比 ≥70%，高价 <8%）→ 慎做中高价
- 价格容忍度强（中高价销量 ≥60%，P75 接近 $30+）→ 优先验证

**高证据密度类目**（参数/认证/兼容复杂）必须做页面深抓 + 图片 OCR，关键证据往往在背标、规格表、A+ 图片里，不在 HTML 文本里。

## 5D 词库：从材料到资产

词库不是堆词。合格词库必须能回答：这个词是否相关、属于什么属性、应该进页面还是广告、是否要否词、能否沉淀成词根。

**5D 词库评分五维度**：需求强度（有没有购买意图）、产品相关性（匹配度）、竞争压力（CPC 是否可承受）、利润承受（CVR 预期下是否有毛利）、时间价值（常青/季节/衰退）。

**词到页面和广告的路由**：
- 核心品类词 → 标题前部 + SP-KW 精准
- 属性词 → 标题/五点/附图 + SP-KW/SBV
- 场景词 → 五点/A+/视频 + SP-KW/SBV/SD
- 痛点词 → 五点/A+/FAQ + SP-KW/SP-PT
- 噪音词 → 否词

**团队质控**：分片初判 → 交叉复核 → 一致率统计 → 争议词会议 → 活规则更新。一致率低说明规则不够清楚，不能急着把词库导入 Listing 或广告。

## 广告架构：选战场优先于选词

**G-M-R 三层架构**（发现 / 验证 / 收割）：广告的第一问题不是"投哪个词"，而是"选哪个战场、用哪类广告、服务哪个判断"。

**七类预算池**（每池有明确任务，不是平分预算）：
- **探索池**：SP-AUTO/Broad/Category PT，发现新词和新 ASIN
- **验证池**：Phrase/精选 ASIN/SBV，测试意图稳定性
- **收割池**：Exact/核心 ASIN，独立衡量稳定赢家商业价值
- **攻击池**：已验证竞品拦截/弱竞品/高价邻近，争夺可赢战场
- **防守池**：自有 ASIN/品牌词/复购路径，防止后链路流失
- **品牌池**：SB/SBV/Store/SD，产品线教育和新客沉淀
- **预备池**：为 Deal/旺季/异常修复保留弹性

**ASIN 战场分层**：高相关竞品池 → 已验证竞品拦截池 → 重点攻克池 → 高价邻近池 → 弱相关低价池 → 类别定位池 → 自有防守池。新 ASIN 不能直接按已验证标准投放。

**预算池阶段比例**：冷启动（探索高/收割低）→ 爬坡（收割高/探索中）→ 稳态（收割高/防守高）→ 大促（预备高）→ 救火（探索低/预备高）

**大货前流量成本验证**：不建议直接用大货库存换学习——先小样本验证核心词的最低有效 bid、实际 CPC 和点击规模。若核心流量需要远高于 Breakeven CPC，先回到价格带和产品定义，而非直接扩大首批库存。

## 定价：可测试区间而非固定组合

价格不是一个点，而是五条线构成的区间：
1. **成本安全线**：采购+包装+质检+头程+佣金+FBA+Coupon+退款损耗
2. **广告容忍线**：成本安全线 + 预期 CPA（判断广告订单是否可承受）
3. **目标利润线**：成本安全线 + 目标利润（判断长期经营价值）
4. **转化测试线**：2–3 个 Sale Price/Coupon 组合，上线后根据 CTR/CVR 调整
5. **上限锚点线**：参考竞品价格带，避免脱离市场认知

**Sale Price 与 Coupon 联动测试**：看三段漏斗——曝光 → Coupon 领取 → 核销结算。领取率高但核销率低，说明用户被促销标识吸引进来，却在页面、Review、价格或信任环节流失，不应机械加大折扣，而要检查页面。

**Coupon 内部风控线**：由贡献毛利、价格基准、评价风险、订单质量和 Seller Central 当前政策共同决定，不是通用固定比例。

## 视觉框架：叙事主张驱动设计

**页面叙事主张**：正式设计启动前，项目负责人必须先写一句话——"给[目标用户]，在[使用场景/搜索意图]下，提供[产品形态/核心属性]的[核心解决方案]，通过[证据/规格/机制/包装承接]降低[主要顾虑]，最终形成[购买理由]。"这句话统一运营/文案/设计/广告/合规所有判断。

**五层叙事结构**：第一层（相关性判断）→ 第二层（核心利益确认）→ 第三层（原因与证据）→ 第四层（使用与风险降低）→ 第五层（品牌与场景收口）

**主图三档验收**：2000px 原图验收 → 600px 移动端验收 → 148x148 缩略图验收（与 5–10 个竞品并排，1 秒内能看出品类和差异）。主图大图好看但缩略图不可读，先反查包装正面层级，不是让设计师继续"加高级感"。

**包装正面的特殊地位**：亚马逊主图不允许后期添加营销文字，因此真实印刷在包装正面的品牌/品类/规格/核心属性是首图中最重要的合规信息表达阵地。

## D0-D90 上架后经营总控

**四个决策门**：

| 门控 | 核心判断 | 可选结论 |
|-----|---------|---------|
| Day 7 | 有无相关曝光/有效点击/可承受 CPC，硬错误排除 | Continue / Fix Setup / Pivot Target / Hold |
| Day 30 | 基本 CVR / Coupon 核销 / 早期信任反馈 | Scale / Fix Page / Fix Price / Pivot Target / Hold |
| Day 60 | 自然份额 / TACOS 改善 / 库存现金可承接增长 | Scale / Limit Inventory / Profit Fix / Defend |
| Day 90 | 是否值得继续补货/稳态/扩产品线 | Go / Defend / Extend / Pivot Product / Kill |

**五阶段经营仪表盘**：冷启动（获取有效曝光和相关点击）→ 漏斗迁移（把赢家从探索池迁入控制池）→ 转化修复（提高页面承接和价格结构效率）→ 利润寻顶（退坡 Coupon，提升贡献毛利）→ 稳态防守（保护自然份额、库存、产品线路径）。每周经营会必须先判断"当前处于哪个阶段"再决定看哪些指标。

**搜索词迁移 SOP**：新增目标 + 源活动隔离 + 记录来源，三步同时做。否则 Broad/Phrase/Exact/Auto/PT 会互相抢量，无法判断哪个位置真正有效。

**库存-广告联动放量规则**：
- 库存绿 + 现金绿 → 扩赢家预算
- 库存黄 + 现金绿 → 限探索池，谨慎强券
- 库存红 → 停止攻击型扩量，只保防守和最低有效流量
- 现金红 → 暂停非必要扩量，停止高费用促销

## 数据置信度：行动前先问"数据够不够"

每个广告/定价动作必须先标注 Data Confidence：

| 置信度 | 条件 | 可以做 | 不应做 |
|-------|-----|-------|-------|
| 高 | 样本足够，已过归因延迟，无异常干扰 | 迁移/否词/降 bid/扩预算/调价 | — |
| 中 | 有方向性信号，样本/窗口不足 | 小幅调 bid/保守迁移/页面修复 | 大幅关停或大幅扩量 |
| 低 | 点击少/刚上线/刚改价改图/断货异常 | 观察/补数据/查设置错误 | 根据 ACoS/CVR 做硬动作 |

**归因安全规则**：大幅降价/关停/否词前，避开 48 小时归因冻结区。相关词没转化，先检查页面和价格，不要先否词。

## 反螺旋规则：防止多变量叠加失控

七条硬规则：
1. 单次 bid 调整上限 5–20%，数据越弱动作越小
2. 大动作后设 24–48 小时冷却期，不连续大调
3. base bid + placement + dayparting 叠加后不超 Breakeven CPC
4. 库存或现金黄灯时，不做攻击型扩量
5. 页面没有修复前，不用加预算掩盖 CVR 问题
6. 不在同一天同时提高多个广告杠杆
7. 新品稀疏数据阶段不根据几小时无订单直接关停

## Go/Pivot/Kill 决策框架

| 决策类型 | 触发条件 |
|---------|---------|
| Scale | CTR/CVR/CPA 有效，库存和现金可承受 |
| Hold | 指标改善但样本不足，归因仍不成熟 |
| Pivot Page | 点击有效但转化差，页面/规格有摩擦 |
| Pivot Target | 页面可转化，但广告战场不匹配 |
| Pivot Product | 多轮修复后核心差评仍指向产品事实 |
| Defend | 核心词/ASIN 有稳定收益但竞争加剧 |
| Kill | 经济模型失效/库存现金不可承受/合规风险高 |

**Pivot 类型细分**：Pivot Setup（硬错误）→ Pivot Target（战场错位）→ Pivot Page（转化不足）→ Pivot Price（价格带不匹配）→ Pivot Inventory（库存/现金限制）→ Pivot Product（产品事实问题）。只有前五类都排查过，才进入 Pivot Product 或 Kill。每次 Kill 必须输出反向学习清单，不允许只说"这个品不行"。

## 周度经营飞轮

固定结构：数据输入 → 诊断（相关性/转化/利润/满意度四层）→ 重构 → 验证（明确窗口和指标）→ 放大（只有完成验证的动作才能放大）。

**动作优先级**：修硬错误（第一优先）→ 修相关性 → 修转化 → 修利润 → 修库存现金 → 放大赢家。未修完硬错误，不加广告预算。

**结论五类**：Scale / Hold / Fix / Pivot / Kill。周会不能形成带负责人和复查日期的动作，就只是报表朗读。
