# 亚马逊关税与落地成本（Amazon Tariff & Landed Cost）

落地成本用于回答“商品真正到达目标市场或仓库时，每件成本是多少”。它把采购价、国际运输、关税、税费和清关物流费用放进同一个模型，避免只按 FOB 或运费判断跨境利润。

## 核心公式

```text
落地总成本 =
  FOB 货值
  + 国际运输
  + 保险
  + 进口关税
  + VAT / GST（如适用）
  + 清关费用
  + 港口费用
  + 目的国内陆运输
```

```text
单件落地成本 = 落地总成本 / 可销售数量
```

单件落地成本应作为 [[amazon-unit-economics]] 中“产品成本 + 入仓运输”的真实输入，而不是与其重复计费。

## 必要输入

| 输入 | 作用 |
|---|---|
| 产品描述 | 辅助确定商品归类 |
| HS Code | 连接产品与适用关税规则 |
| 原产国 | 决定原产地规则、额外关税与贸易协定资格 |
| 目的国 | 决定进口关税、VAT / GST 与清关规则 |
| FOB 货值 | 货物计价基础 |
| 数量 | 将总成本折算到单件 |
| 国际运输与保险 | 形成运输相关成本基础 |
| 清关、港口、内陆运输费用 | 补全到仓前的实际支出 |

任何关键输入缺失时，只能输出情景估算，不能声称得到了准确落地成本。

## 计算流程

### 1. 确定贸易路线

先明确：

```text
原产国 → 目的国
```

同一商品从不同原产国进入同一市场，可能适用不同关税、额外税项或贸易协定。不能只看发货地；原产国与运输起点并不总是同一概念。

### 2. 确定 HS Code

HS Code 是关税计算的入口。产品描述只能生成候选编码，最终编码应以报关资料、专业归类意见或目的国官方系统为准。

需要记录：

- 候选 HS Code
- 归类依据
- 尚不确定的产品属性
- 最终由谁确认

若归类错误，后续税率再精确也没有意义。

### 3. 检查基础关税与额外关税

对目标路线分别检查：

- 基础进口关税
- 针对特定原产国或产品的额外关税
- 反倾销、反补贴或其他特殊税项是否适用
- 贸易协定是否提供优惠税率
- 使用优惠税率需要满足哪些原产地证明条件

源方法提及 Section 301、USMCA、EVFTA 与 RCEP 等示例，但这些政策及适用范围会变化。它们应作为**核验清单**，不能直接作为当前结论。

### 4. 计算税前到岸成本

```text
税前到岸相关成本 = FOB 货值 + 国际运输 + 保险
```

不同司法辖区对关税计税基础的定义可能不同，应按目的国当前规则确认，不应把上述结构直接当作所有国家的法定计税公式。

### 5. 计算关税与消费税

分别录入经核验的：

- 基础关税率
- 额外关税率
- VAT / GST 税率及计税基础
- 其他适用税费

税率和计税基础都必须注明来源与核验日期。

### 6. 补全清关与目的地物流

加入不会自动出现在关税率中的实际费用：

- 报关或清关服务费
- 港口及操作费用
- 查验或文件费用
- 目的国内陆运输
- 其他到仓前费用

### 7. 折算单件落地成本

```text
单件落地成本 = 落地总成本 / 可销售数量
```

若存在损耗、样品、质检淘汰或不可售数量，分母应使用预计可销售数量，而不是采购总数量。

## 情景比较

同一产品至少可以比较三类情景：

| 情景 | 变化变量 |
|---|---|
| 不同原产国 | 关税、贸易协定、运输成本 |
| 不同目的市场 | 关税、VAT / GST、清关与内陆物流 |
| 不同运输方案 | 运费、保险、时效与库存占用 |

比较结果至少输出：

- 落地总成本
- 单件落地成本
- 关税与税费占比
- 运输与目的地费用占比
- 使用的税率、规则来源与核验日期
- 尚未确认的风险项

## 应用边界

- HS Code、关税、额外关税、VAT / GST、贸易协定和清关规则都是动态且具司法辖区差异的输入，必须实时核验。
- 本方法是成本结构与计算流程，不构成税务、海关或法律意见。
- 不应把源仓库列出的税率区间或国家示例直接写入长期模型。
- 贸易协定优惠不只取决于路线，还可能依赖原产地规则和证明文件。
- 落地成本是单位经济输入，但不包含 Amazon 销售佣金、FBA 配送、广告等销售阶段费用。
