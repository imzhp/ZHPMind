# 亚马逊后端关键词整理（Amazon Backend Keywords）

后端关键词用于承接与商品高度相关、但没有自然进入标题、五点和描述的搜索表达。本页提供一个“去重 → 筛选 → 排序 → 压缩 → 校验”的整理框架；源文件只有能力清单，因此不补充未被来源支持的索引规则或具体算法。

## 输入

开始前需要：

- 当前标题
- 当前五点
- 当前描述
- 候选关键词清单
- 已知的相关性或搜索量信号
- 目标站点与语言

没有前台 Listing，就无法可靠判断哪些词已经覆盖；没有候选词来源，也不能凭空生成有证据的优先级。

## 整理流程

### 1. 建立候选词池

候选词可以包含：

- 前台文案尚未覆盖的相关词
- 同义词
- 常见拼写变体
- 与目标站点相关的多语言表达

每个候选词都应能说明它与产品的关系。仅仅“可能有人搜”不足以让它进入后端。

### 2. 与前台内容去重

逐项对照标题、五点和描述，移除已经充分覆盖的重复词，把有限空间留给新增覆盖。

去重输出至少包含：

| 关键词 | 前台是否已覆盖 | 是否保留 | 理由 |
|---|---|---|---|
| 候选词 | 是 / 否 | 是 / 否 | 新增覆盖 / 重复 / 无关 |

### 3. 过滤禁止或高风险词

源方法要求过滤：

- 竞品品牌
- 受限声明
- 其他禁止词

具体禁止规则会随站点、类目和政策变化。发布前必须根据当前 Seller Central 规则核验，不能只依赖固定清单。

### 4. 按价值排序

源方法使用两个主要信号：

- 与产品的相关性
- 搜索量信号

相关性应优先于表面搜索量。高搜索量但不准确的词会浪费空间，并可能带来错误流量。

可将候选词分成：

| 优先级 | 判断 |
|---|---|
| 高 | 高相关，前台未覆盖，有较强搜索信号 |
| 中 | 相关，补充同义词、场景或语言覆盖 |
| 低 | 相关性或搜索证据较弱，只在空间允许时考虑 |
| 删除 | 重复、无关、竞品品牌、受限或高风险词 |

### 5. 在字节限制内压缩

源方法以 **250-byte** 作为优化目标：在限制内最大化有效关键词覆盖。

执行时需要：

- 按字节而不是按字符计数
- 优先保留高价值词
- 删除重复覆盖
- 检查多语言字符对字节数的影响

250-byte 是源仓库给出的规则基线，可能随站点或平台政策变化。实际填写前必须核验当前 Seller Central 限制。

### 6. 做前后覆盖比较

整理完成后输出：

- 原候选词数量与字节数
- 删除的重复、无关和风险词
- 最终关键词集合与字节数
- 新增覆盖的关键词
- 因空间不足未纳入的候选词

## 多语言、拼写变体与同义词

源方法将多语言词、常见拼写错误和同义词视为潜在覆盖来源。使用时必须同时满足：

- 与目标站点和买家语言真实相关
- 没有在前台充分覆盖
- 不违反当前平台政策
- 在有限字节中优先级高于其他候选词

它们是候选项，不是必须项。

## 应用边界

- 本方法只整理已有候选词，不替代关键词研究。候选词来源连接 [[amazon-keyword-library]]。
- 250-byte、禁止词与索引规则属于动态平台政策，必须实时核验。
- 源文件未提供具体字节计算算法、索引机制或多语言规则，本页不自行扩写。
- 后端关键词不能弥补 Listing 与产品不相关的问题。
- 覆盖更多词不是最终目标；目标是增加准确、有效且合规的搜索覆盖。
