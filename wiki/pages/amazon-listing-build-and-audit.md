# 亚马逊 Listing 构建与八维审计（Amazon Listing Build & Audit）

本页把 Listing 工作拆成两个模式：新品从关键词与产品信息出发进行构建，现有 Listing 通过关键词缺口与八维评分进行审计。它是一个可重复的构建与诊断框架；与 [[listing-optimization]] 的区别是，本页聚焦**输入组织、关键词覆盖和百分制审计**，后者覆盖更完整的 Listing 优化知识。

## 两种工作模式

| 模式 | 适用场景 | 主要输入 | 主要输出 |
|---|---|---|---|
| 构建 | 新品或重建 Listing | 关键词、竞品、产品信息、语气 | 完整 Listing 草稿与关键词覆盖报告 |
| 审计 | 优化现有 Listing | 当前 Listing、目标关键词、竞品 | 八维评分、缺口分析与修改建议 |

两种模式共享同一个原则：Listing 文案不是先写完再塞关键词，而是先确定关键词优先级，再让标题、五点和描述分别承担不同任务。

## 构建模式

### 1. 汇总关键词来源

关键词可以来自：

- 已有关键词清单
- 竞品标题、五点和描述中出现的有效词
- 其他已完成的关键词研究结果

合并后去除明显无关项，再进入优先级分层。竞品词只能作为候选输入，不能因为竞品使用就默认适合自己的产品。

### 2. 关键词四层分级

| 层级 | 主要位置 | 判断逻辑 |
|---|---|---|
| Primary | 标题 | 高优先级、高相关，必须覆盖 |
| Secondary | 五点 | 中高优先级，适合连接功能与利益 |
| Tertiary | 描述 | 补充场景、属性和长尾表达 |
| Long-tail / Remaining | 自然分布或后端词 | 文案中未覆盖但仍有价值 |

源方法以搜索量和相关性确定优先级。没有可靠搜索量时，应标注判断依据不足，避免凭感觉制造精确排序。

### 3. 收集产品事实

构建前至少确认：

- 产品名称与类型
- 品牌
- 材质、颜色、尺寸、重量、容量、数量等属性
- 3–5 个关键特征与差异点
- 目标人群
- 主要使用场景
- 包装内包含什么

关键词不能取代产品事实。任何不能由产品真实属性支持的卖点或关键词，都不应进入 Listing。

### 4. 选择表达语气

源方法给出四种语气：

| 语气 | 表达重心 | 较适合的场景 |
|---|---|---|
| Professional | 参数、可信度、权威感 | 工具、电子、B2B |
| Friendly | 利益、场景、亲近感 | 厨房、生活方式、礼品 |
| Urgent | 问题解决与行动导向 | 健康、安全、季节性 |
| Luxury | 感官、质感、稀缺性 | 美妆、时尚、高端商品 |

语气影响表达，不应改变事实或制造无法证明的承诺。

### 5. 构建各内容组件

#### 标题

源方法给出的结构基线：

```text
品牌 + 主关键词 + 关键属性 + 次关键词 + 差异点
```

主关键词尽量靠前；避免全大写和未经证明的“最佳、第一”等宣传性声明；尺寸、颜色、数量等影响搜索和购买判断的属性应在适合时出现。

#### 五点描述

五点分别承担不同任务：

1. 核心特征与主关键词
2. 关键使用场景与次关键词
3. 材质、质量与可信信息
4. 包装内容或兼容性
5. 差异点、保障或补充价值

每一点都应从功能走向买家利益，并自然覆盖关键词，而不是把关键词堆成句子。

#### 描述

```text
问题 / 痛点 → 功能与利益展开 → 包装内容与行动收束
```

描述用于展开五点没有讲清的逻辑，并覆盖尚未自然出现的相关词；不应逐句重复标题和五点。

#### 后端搜索词

未能自然进入前台文案但仍相关的关键词，转入 [[amazon-backend-keywords]] 继续处理。

源方法给出的标题、五点和描述字符上限属于平台规则基线，可能因站点、类目与政策变化而不同。落地前必须核验当前 Seller Central 规则。

### 6. 关键词覆盖检查

建立覆盖表：

| 关键词 | 标题 | 五点 | 描述 | 后端候选 | 状态 |
|---|---|---|---|---|---|
| 目标词 | 是 / 否 | 是 / 否 | 是 / 否 | 是 / 否 | 已覆盖 / 缺失 |

源方法提供的启发式评分：

- 覆盖率 ≥90%：优秀
- 70–89%：存在小缺口
- <70%：存在显著缺口

覆盖率不能单独代表 Listing 质量。无关词覆盖越多，反而越可能损害可读性与转化。

## 审计模式

### 1. 建立目标关键词集

目标词可来自当前 Listing、已有研究和竞品。先确定要审计什么，再评估缺口；否则“缺词”会变成无限扩张的清单。

### 2. 做关键词缺口分析

对比：

- 当前已覆盖的词
- 竞品覆盖、自己未覆盖的词
- 缺失词的相关性与优先级
- 应加入标题、五点、描述还是后端

竞品拥有但自己缺失，不等于必须添加。先判断它是否真实描述自己的产品与目标人群。

### 3. 八维百分制审计

| 维度 | 分值 | 核心检查 |
|---|---:|---|
| 标题 | 15 | 主词位置、品牌与属性、可读性、移动端截断风险 |
| 五点 | 15 | 是否完整、利益优先、关键词自然、信息清晰 |
| 图片 | 15 | 数量、主图、信息图、场景图、尺寸参照、视频 |
| A+ 内容 | 10 | 品牌故事、对比、生活方式呈现 |
| 描述 | 10 | 可读性、问题到解决方案、补充关键词 |
| 定价 | 10 | 竞争力、促销信息 |
| 评论 | 15 | 星级、数量、近期评论信号 |
| SEO 覆盖 | 10 | 主词覆盖、长尾词、重复浪费、覆盖率 |
| **总分** | **100** | |

评分的价值是保持审计一致性并暴露短板，不是制造虚假的客观精确度。缺少真实价格、评论或关键词数据时，对应维度必须标明证据不足。

### 4. 输出修改方案

审计输出应区分三类结果：

- 可以直接重写的内容：标题、五点、描述、后端词候选
- 需要卖家采取行动的内容：图片、A+、价格、评论管理
- 当前已经有效、应保留的内容

修改前后都应重新计算关键词覆盖，并说明新增词放在哪里、为什么放在那里。

## 应用边界

- 八维评分是诊断框架，不是 Amazon 官方评分。
- 没有真实关键词数据时，不应声称知道精确搜索量或优先级。
- 竞品内容只能用于发现候选结构与缺口，不能复制文案或未经核实的卖点。
- 所有字符限制、禁止词、图片要求与类目规则都应在发布前实时核验。
- Listing 构建不能替代产品定位；如果产品差异和目标人群不清楚，文案优化只能掩盖问题。
