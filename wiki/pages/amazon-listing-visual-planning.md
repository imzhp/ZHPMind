# 亚马逊 Listing 视觉规划（Amazon Listing Visual Planning）

本页将 Listing 图片规划与产品摄影规划合并为一个方法：先定义每张图片承担的购买问题，再形成拍摄清单、信息图简报、场景图简报和测试计划。源文件只提供能力清单，因此本页严格保留其框架边界，不补充具体摄影参数或外部平台规则。

## 核心原则

Listing 视觉不是“拍几张好看的图”，而是一组有明确分工的购买信息。规划时要同时处理：

- 商品是否清楚、可信
- 核心功能是否一眼可见
- 买家是否能理解尺寸与比例
- 买家是否能想象真实使用场景
- 小屏幕上文字和重点是否仍然可读
- 哪些视觉假设需要通过测试验证

## 输入清单

规划前收集：

- 产品与变体信息
- 目标人群
- 核心功能与差异点
- 主要使用场景
- 尺寸、容量、配件与包装内容
- 当前图片及已知问题
- 可用预算
- DIY 拍摄或专业拍摄的资源边界

输入不完整时，应明确哪些视觉决策只是暂定假设。

## 七图结构

源方法提出“主图 + 6 张辅助图”的七图规划。它是一种组织基线，不是所有类目和站点的固定要求。

| 图片角色 | 主要任务 |
|---|---|
| 主图 | 让买家快速识别商品本体 |
| 功能信息图 | 展示核心功能与卖点 |
| 场景图 | 把商品放入目标人群的真实使用情境 |
| 尺寸 / 比例图 | 消除对大小、容量或适配关系的误解 |
| 细节 / 材质图 | 展示影响信任和购买判断的细节 |
| 包装内容 / 组合图 | 说明买家实际收到什么 |
| 补充价值图 | 承担剩余的重要购买问题或测试假设 |

辅助图的具体排序应由买家最需要先解决的问题决定，而不是机械套用固定顺序。

## 主图规划

源方法要求关注：

- 白色背景
- 商品在画面中的填充比例
- 光线与商品清晰度
- 是否符合 Amazon 当前图片要求

源文件提及主图 85% 填充等要求，但平台规则可能变化。正式制作与上传前必须核验目标站点和类目的最新要求。

主图简报至少说明：

- 拍摄对象与变体
- 商品朝向
- 必须清楚呈现的形态与部件
- 不应出现的道具、文字或干扰元素
- 当前规则核验结果

## 信息图规划

每张信息图只承担一个主要信息任务：

- 核心功能 callout
- 尺寸或容量
- 材质与结构
- 使用步骤
- 配件与兼容性

信息图简报应写清：

```text
这张图要回答的问题
要展示的产品事实
需要标注的文字
画面中的视觉重点
移动端缩小后必须仍可读的内容
```

不要让一张图同时承载过多卖点；源方法强调移动端可读性，信息优先级应高于装饰。

## 场景图规划

场景图简报包含：

- 目标人群
- 使用场景
- 人物或模特需求
- 环境与道具
- 商品在场景中的动作
- 这张图要传达的利益或感受

场景必须服务于真实使用方式，不能通过不真实比例或不支持的使用方式制造误导。

## 尺寸与比例参照

尺寸 / 比例图用于减少买家对大小、容量和适配关系的误判。可在简报中明确：

- 必须展示的尺寸
- 使用何种参照物或使用情境
- 是否需要标注兼容范围
- 哪些信息容易在移动端丢失

## 拍摄清单

把视觉策略转成拍摄执行清单：

| 镜头 | 图片角色 | 拍摄对象 | 场景 / 道具 | 必须呈现的信息 | 后期需求 |
|---|---|---|---|---|---|
| 1 | 主图 | 商品本体 | 白底 | 形态与清晰度 | 规则核验 |
| 2–7 | 辅助图 | 按规划填写 | 按简报填写 | 每张一个主要任务 | 信息图 / 裁切等 |

源方法提到灯光设置与 DIY / 专业摄影预算比较，但没有提供具体判断公式。落地时可记录预算和资源选择，不应从该源虚构具体灯光方案或成本标准。

## 移动端检查

每张图都要在小尺寸下检查：

- 文字是否仍可读
- 商品主体是否足够突出
- callout 是否过多
- 关键尺寸与利益是否被裁切
- 视觉重点是否无需放大即可理解

## A/B 测试计划

源方法要求为图片建立 A/B 测试策略。测试时一次只改变一个主要假设，例如：

- 主图构图
- 第一张辅助图承担的问题
- 信息图与场景图的排序
- 某个核心卖点的表达方式

测试计划至少记录：测试假设、变体差异、观察指标与结论。源文件未定义具体指标或样本标准，因此本页不补充固定阈值。

## 应用边界

- 本页是视觉规划框架，不是具体摄影技术手册。
- 源文件没有提供完整的方法论正文、类目差异或测试统计标准，不能据此虚构细节。
- 图片数量、主图背景、填充比例与其他合规要求必须按当前站点和类目实时核验。
- 图片只能表达真实产品事实，不应通过场景、比例或后期处理误导买家。
