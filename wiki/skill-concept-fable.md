# skill: concept-fable

## 设计意图

把抽象概念变成具体故事,绕过术语硬啃。

学习者(尤其是非领域专家)遇到抽象概念,常见状态是"听过、点头、转头就忘"。这不是讲解不够努力,而是大脑对抽象概念的留存机制偏弱——故事是大脑唯一愿意主动复述的载体。

这个 skill 让 AI 围绕一个指定概念写一则寓言,寓言全程不出现概念名称,只在结尾让读者意识到讲的是什么。配套两个检验问题,确保学习者真的理解,而不只是被故事逗乐。

## 来源

- **原版**:Anthropic Amanda Askell 2026 年 4 月访谈分享(Claude 性格对齐团队负责人,Claude 宪法主笔)
- **优化版**:微信公众号文章(2026-05),在原版基础上加了三个东西:
  - 防套路约束(意象/地名/结构/角色/开头黑名单)
  - 指定具体 concept 而非随机抽领域
  - 两个检验问题(理解检验 + 迁移检验)

## 适用边界

### 适用
- 关系型 / 感觉型概念(陌生化、奥德赛时期、漏斗、心理账户、路径依赖)
- 抽象哲学概念
- 需要"直觉锚点"的方法论入门
- 团队内部分享前的开场素材
- 个人学习新概念时的"第一次理解"

### 不适用 / 慎用
- **结构型概念**(FIFO 库存计价、OKR 的 KR 量化规则、数据库范式)——寓言会掩盖关键结构
- **需要精确边界的术语**(PRD 字典、合同条款、财务定义)——寓言的"模糊接近"会污染精度
- **给分销商 / 客户的对外沟通**——B2B 场景对方要专业感,不要被讲故事

### 关键风险
寓言通过隐喻接近概念,学习者可能把隐喻里某个无关细节当成概念核心。**检验问题不是装饰,是核心防线**——跳过检验等于把误解锁进记忆。

## 使用方法

### 基础用法
把下方完整 prompt 复制到 Claude 主对话,把 `{concept}` 替换成要学习的概念。读完寓言后**必须回答两个检验问题**。

### 进阶用法(集成进 ZHPMind 学习工作流)
1. 学习新 concept 时,先写定义 + 要点(常规)
2. 跑这个 skill,把寓言放在概念页"直觉锚点"段落
3. **回答两个检验问题(写在 vault 里,不是脑子里)**
4. 答出来 → 信度标 🔵(已掌握);答不出来 → 标 🟠(能记住但不会用),回头补

## Prompt 模板

```markdown
围绕 **{concept}** 这个概念,写一则寓言来完整地解释它。要像真正的寓言那样间接讲,不要直接点破。

## 一、寓言体感
- 篇幅:1000 字以内。靠一个核心场景、一两次转折把意思撑起来。
- 世界观:虚构,可以拟人化,可以在一个不写实小世界里,也可以是日常微观场景。
- 角色:不超过三个,最好两个。它们的互动本身承载寓意。
- 揭示节奏:全程不出现概念名称,不用该领域术语。结尾才让读者隐约意识到讲的是什么。
- 叙事纪律:让情节和细节承载意义,不要让角色跳出来当解说员。

## 二、防套路自检(动笔前过一遍)

意象黑名单:钟、河流、镜子、迷宫、织布机、地图、灯塔、棋盘、回声、影子、沙漏、风、蜡烛、种子、桥、星辰、蝴蝶、蛛网。

地名黑名单:不写"回声城""记忆之村""遗忘之海""寂静谷"这类文艺化虚构地名。给个普通地理名词,或不命名。

结构黑名单:旅行者求教智者 / 村庄异象众人顿悟 / 孩童一句话点醒大人 / 师徒辩难 / 临终遗言。

角色黑名单:钟表匠、图书管理员、隐士、说书人、老船夫、酿酒师、铁匠、抄经人。

开头黑名单:"从前有个地方……""某天某人遇见某事……""在很远的山里……"。直接进入场景。

## 三、切入角度

优先考虑(可组合):
- 非人类视角:一件工具、一只动物、一种植物、一个机构在自述
- 具体的现代职业和场景:理赔员、电梯保养工、菜市场摊主、夜班护士、外卖站长、二手房中介、分拣员
- 微观尺度:一次交易、一次门诊、一通电话、一次拆卸,内部发生的事

核心原则:让故事的具体性把概念裹住。

## 四、输出格式

### 第一部分:寓言正文
直接输出故事,不加标题、不加引导语。

### 第二部分:概念解析
1. 这个概念叫什么、属于哪个流派或学科、核心定义是什么
2. 逐一对应:故事里的哪些元素映射到概念的哪个部分

### 第三部分:检验问题
向我提两个问题:
1. 理解检验:检验我是否真正理解了概念的核心,而不只是记住了表面的故事情节。问题要具体可答。
2. 迁移检验:检验我是否能把这个概念迁移到相关领域,让我自己举例回答。问题要具体可答。

不要写成"你怎么看待这个概念"这样空泛的开放题。
```
