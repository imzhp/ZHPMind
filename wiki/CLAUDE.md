# Wiki 操作手册

仅用于正式 `wiki/` 操作；普通剪藏、个人笔记和对话遵循根 [AGENTS.md](../AGENTS.md)，不套用本手册的页面字段与入库步骤。
保留文件名及主要章节编号以兼容现有引用。历史工作流描述不覆盖当前项目约定。

## 1. 操作范围

用户要求整理入 wiki、维护参考页或来源时，读取与任务相关的文件，再完成限定范围的编辑。
“看看”“聊聊”“记下我的想法”不自动等于完整蒸馏。现有书页、教程整理不自动代表 Haopeng 的理解。

## 2. 文件与来源

- `wiki/pages/` 保持平铺；不批量重命名既有页。新正式页使用简短英文 kebab-case，中文名称可放 title/aliases；此约定不限制 wiki 以外的个人笔记。
- `wiki/raw/` 保留有理由保存的来源，可先保存后阅读，不要求先蒸馏。已有原文只读，分析与修订说明另写。
- 新归位的书/课程全文使用 `wiki/raw/assets/books/书名-作者.{epub,pdf,docx,md}`；作者从来源核实，未知时询问或明确未知，不猜姓名。已有其他来源路径本轮不迁移。
- 普通文章可存 raw 顶层，媒体在 raw/assets；移动来源必须检查引用和重名，未授权时保留原位。读完一本书不是自动移动它的理由。
- `projects/`、`outputs/`、`archive/` 不因 wiki 编辑自动变更。`wiki/log.md` 只追加。

## 3. 正式页面兼容规范

### 3.1 类型

正式页继续兼容 `concept`、`method`、`framework`、`person`、`article`、`book`、`reflection`、`snapshot`、`moc`、`skill`。
类型描述内容形式，不代表经过实践、已被用户认可或必须完成某个工作流。

### 3.2 Frontmatter

为了不破坏现有索引和扫描器，新正式页（index 除外）仍使用下列字段；个人笔记不需要这些字段。现阶段不批量删除或迁移旧字段。

```yaml
---
title: "页面标题"
aliases: []
type: article
tags: []
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: []
source_count: 0
discussions: []
---
```

- `sources` 只列相对于 `wiki/raw/` 的实际文件路径，如 `assets/books/书名-作者.md`；`source_count` 等于该列表长度，由编辑工具保持一致。
- 对话、项目材料或仅保留 URL 的来源，允许 `sources: []`、`source_count: 0`，在正文注明真实日期、文件位置或链接，不伪造 raw。
- 正式页标签用英文小写连字符，不用斜杠；可以为空。不补造标签以满足数量。
- `created` 保留，实质内容修订时更新 `updated`；纯排版不必改日期。只有实际保存了对话内容，才将日期加入 `discussions`。
- 来源模型/commit SHA 等已有 provenance 字段保留。来源数不等于独立证据数量。

### 3.3 正文

围绕实际问题组织，不强制固定栏目。区分作者主张、AI 摘要、个人理解与待验证判断；外部材料不改写成用户经历。
关键摘录、数据与论断指向来源位置，无法核实的明确标注。标题不在文件名、属性和正文中机械重复；旧页无需为排版全库重写。

### 3.4 人物与反思

已有 Compiled Truth / Timeline / References 结构保留；新反思不强制三段式。
事实与解释分开。后续理解注明时间，不能把 AI 解读写成用户确认的身份或心理特征。
Timeline 不因超过行数自动压缩或归档；发现事实错误时保留纠正依据，不以 append-only 为由保留已知错误。

### 3.5 书页

书页可以是选读笔记、来源摘要或相关疑问，不强制完整摘要、Mirror 占位或按章镜射。
只有明确执行完整 book-mirror 时，采用该 skill 的“核心总览 + 镜射（按章）”组装结构。

### 3.6 命名

新页先查现有同主题页面与文件名，不重复建页。导航页沿用 `{topic}-moc.md`，技能反思页沿用 `skill-{name}.md`。
业务实体优先沿用现有对外标识与 aliases，不为规则统一改旧名。

### 3.7 链接

有意义的关联使用 `[[page-name]]`；同名有歧义时使用相对于 vault 的明确路径。
不规定最低链接数，不为出现的每个术语建页。有意保留的未创建主题与误删导致的失效引用要区分。

### 3.8 技能反思页

仅在有值得回看的经验时维护，不因新增或修改 skill 强制再写一页。
既有 `type: skill` 页保持 `status` 与 `references` 字段，指向真实执行体；状态依据验证结果填写。
写设计理由、实际问题与未解决项即可，不复制整个执行流程。规范在 skill，历史经验不是新授权。

### 3.9 直觉锚点

仅在用户需要类比/寓言帮助理解时，调用项目的 concept-fable。
保留比喻的对应关系和不适用边界；不把它当作证据。不自动批量添加或生成检验作业。
选定内容可放在“定义”之前；具体候选与检验格式按 skill，不约束普通解释。

## 4. Index 与 MOC

保留现有格式与排序，不重排无关条目。新增、改名或经授权删除正式页时，更新对应索引条目和准确页数；摘要、类型、来源数变化时，只更新受影响条目。
正文措辞或排版变化不必触碰索引。MOC 只在确有导航需要时维护，不为数量阈值建 MOC。
沿用分区：concept/method → Concepts & Methods；framework → Frameworks；person → People；article/book → Articles & Books；reflection → Reflections；snapshot → Snapshots；moc → MOCs；skill → Skills。

## 5. 日志

正式新页入库、重要事实修订或结构调整，在 `wiki/log.md` 追加一条简短记录；一次任务一条，不按文件拆分。
个人随想、只读查询、未保存的候选和纯排版不记 wiki 日志。系统规则变更记根 changelog，不重复两份。

```markdown
## [YYYY-MM-DD] operation | 主题

- **Pages created**: [[new-page]] 或 none
- **Pages updated**: [[existing-page]] 或 none
- **Sources touched**: 实际变更的来源或 none
- **Note**: 关键改动、检查及未完成项
```

日志不能把自检标成独立模型评审，也不以模板要求编造操作。

## 6. Distill 工作流

仅在明确要求蒸馏或整理入 wiki 时使用：
1. 核实指定来源，读所需内容；大文件用工具分块，报告实际覆盖范围，不把节选说成读完整本。
2. 查同主题既有页，选择满足请求的最小产物。默认不拆出所有实体/概念，也不覆盖不属于本次范围的内容。
3. 按 §3 写正式页或用户要求的草稿，标明来源归属；只做摘要不冒充个人方法论或实践结论。
4. 核对关键原文、数字、引用与适用边界。普通蒸馏不默认调用外部模型；指定评审流程见 §13。
5. 来源归位只在本次授权包含归位/入库流转时执行，并检查移动后的引用；否则保留原位、准确引用。
6. 按 §4–5 更新实际需要的导航和日志，报告变更与未完成项；Git 见 §14。

## 7. Query 工作流

从问题出发搜索相关笔记，需要了解全貌时再读 index/MOC，不要求每次先读完整索引。
回答区分本库记载、原始证据和当前推断。查询不自动生成新页、日志或反思任务。

## 8. Mirror 工作流

日常讨论“这对我有什么启发”时，只围绕具体观点与相关经历交流，不自动进入整书镜射，也不自动写入人物页。
明确请求按章 book-mirror 时，读取 `.codex/skills/book-mirror/SKILL.md`；保留确定性拆章、staging、事实锚点、逐章评审、人审与 B 结构组装。
共鸣由用户判断。读取相关个人素材不等于允许将其全量发送给外部模型，评审范围须在授权内。

## 9. Reflect 工作流

用户要求保存反思时，在指定笔记中保留原意、疑问与后续补充；不自动把普通保存升级成正式 reflection 页。
明确要求整理入 wiki 时再按 §3–5 执行。未经确认的 AI 解释不得写入身份档案，不自动传播。

## 10. Harvest 工作流

仅在明确要求从项目中整理经验时使用。注明实际项目、情境、结果与适用边界，不从一次成功推断普遍规律。
只写本次指定产物，不自动改项目文件、人物页或全部相关概念；正式入库按 §3–5。

## 11. 直接影响修正（Propagation）

取消 distill/reflect/harvest 后的泛化传播。
本次明确修正的事实、路径或名称若使直接引用失真，在授权范围内同步修正并核对；主题相近不是改写理由。
涉及身份解释、额外页面、大范围迁移或删除时，列清影响后取得相应授权，不用传播扩大任务。

## 12. Lint 工作流

仅在要求维护检查时运行，重点是来源丢失、同名歧义、真实断链、数据格式和此次改动的直接影响。
先报告问题，再按授权修复。保留既有工具兼容要求，但不把普通笔记缺字段、长文、未创建主题或缺少反链当作错误。
不得依据页面修改次数、inbox 数量、MOC 覆盖率等判断认知健康或批量生成学习任务。

## 13. 质量与专项评审

- 普通记录核原意，摘录/摘要核原文；重要分析核原始证据、计算及适用条件，必要时建议独立来源或评审。
- OpenAI 作者与同家系模型自检不算独立家系验证；多模型一致也不保证正确。
- 现有 `~/.hermes/skills/cross-eval/SKILL.md` 与 `~/.hermes/scripts/cross-eval-run.py` 是专项执行体，本次没有修改其模型数量、付费调用或 gate。
- 明确选择现有 cross-eval / 按章 book-mirror 时，遵守执行体要求，不以日常规则豁免伪造专项 pass。报告区分未运行、调用失败、内容问题和通过。
- book-mirror 的 `--source-ref` 仍需包含书章、`wiki/pages/zhanghaopeng.md` 及 draft 各行引用的实际锚点。若外发范围未获授权，停在草稿，不静默省略来源或扩大外发。
- 可回滚遵循根 AGENTS 的单写者约定，不承诺一轮内容编辑对应一个独立 commit。

## 14. Git 版本控制

遵循根 AGENTS.md 的 mini watcher 单写者规则；内容编辑不自行 add/commit/push。
现有 ignore 策略不变：Markdown 来源可跟踪，二进制书源不进 Git，历史 staging 大部分被忽略。
本地文件存在、Sync 同步和 Git 备份是不同状态；未验证不宣称已完成备份。

## 15. Wiki as Context

本库是可查资料，不是事实权威。涉及已记录主题时读相关页，必要时回到原始来源或核实新近信息。
旧画像和重复转述不构成独立证据；用户当前陈述优先用于核对过时背景。无关个人档案不作为所有任务的前置输入。

## 16. 语言

正文默认简体中文，保留必要的原文术语与准确引文。代码、路径和字段不翻译。
面向未来阅读组织内容，而不是记录模型内部工作过程。

## 17. 专项入口

- 按章书镜：`.codex/skills/book-mirror/SKILL.md`
- 概念寓言：`.codex/skills/concept-fable/SKILL.md`
- 执行技能以项目副本为准，历史 handoff 仅提供来源和背景。
- 旧版手册及设计的历史记录在 Git；当前变更记录见根 changelog。后台服务是否运行不由本文声明。
